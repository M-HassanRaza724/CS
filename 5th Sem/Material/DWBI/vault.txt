### 3. Exact Text Description of Each Stage (To Write Below Your Diagram in Exams)

If an exam question asks you to explain the diagram above, write these **four short bullet points** underneath your sketch to guarantee full marks:

1. **Hop 0 — Source Extraction (`LOAD` / `CDC` into Staging Zone):**
Raw data from structured OLTP databases (3NF), semi-structured JSON/IoT logs, and flat files is extracted via nightly batch `LOAD` or real-time `CDC` (Change Data Capture) into the **Staging Zone**. The Staging tables are **flat, temporary structures** that mirror the source systems. Here, corrupted records are routed to an `Error` table, and every valid row is stamped with `Load_DTS` (load timestamp), `Record_Source` (originating application), and a deterministic **Hash Key**.


2. **Hop 1 — Parallel Vault Ingestion (`Staging` $\rightarrow$ `Raw Data Vault`):**
Using the pre-calculated Hash Keys, an automated **insert-only** ETL/ELT process decomposes the flat staging rows into **highly normalized** Data Vault tables **100% in parallel**:


* **Hubs:** Store unique natural Business Keys, Hash Key PK, `Load_DTS`, and `Record_Source`.


* **Links:** Store many-to-many ($M:N$) relationships and transactions between Hubs.


* **Satellites:** Store time-variant descriptive attributes (`Load_DTS` deltas) split by rate of change or source system.




3. **Hop 2 — Business Alignment (`Raw Data Vault` $\rightarrow$ `Business Data Vault`):**
Inside the Vault, ELT transformations apply corporate business rules, standard calculations, and KPIs without altering the raw audit trail. Engineers also populate **Point-in-Time (PIT)** and **Bridge** helper tables to pre-join the normalized Hubs, Links, and Satellites.


4. **Hop 3 — Information Delivery (`Data Vault` $\rightarrow$ `Star Schema Data Marts`):**
Parallel ELT pipelines (or SQL Materialized Views) join the Vault tables (`Hub + Link + Satellite + PIT`) and **denormalize** them into **Kimball Star Schemas** (`Fact` and `Dimension` tables) across departmental Data Marts (`DM 1`, `DM 2`, `DM 3`), allowing BI tools and dashboards in the **Consumer Layer** to query data with sub-second response times.
